# CSE494 (Intelligent NoSQL Databases) — Course Outcomes & Syllabus Unit Mapping

## 1. Course Outcomes (CO1 – CO6) Mapping

| Course Outcome | Description | MediKiosk Implementation & Evidence | Verification / Test File |
| :--- | :--- | :--- | :--- |
| **CO1** | Understand NoSQL database fundamentals, CAP theorem trade-offs, and document-oriented storage vs. relational schemas. | Polymorphic clinical case storage (`allopathic` vs. `ayush` *Dashavidha Pariksha* inside `CaseRecord.history`) without sparse nullable relational join tables; MongoDB connection & health monitoring (`GET /health`). | `server/src/config/db.js`, `server/src/tests/health.test.js`, `docs/schema-design.md` |
| **CO2** | Perform CRUD operations, pagination, projection, and atomic document updates (`$set`, `$push`) using MongoDB and Mongoose. | Full REST CRUD controllers across `User`, `Patient`, `CaseRecord`, and `MedicalDocument`; atomic consent updates (`PATCH /api/patients/:id/consent`); physician review edits (`PATCH /api/cases/:id/review`); cascading deletes on patient removal. | `server/src/controllers/*.js`, `server/src/tests/api.test.js` |
| **CO3** | Design NoSQL schemas using embedding vs. referencing patterns (1:1, 1:N, M:N) and enforce schema validation via `$jsonSchema`. | Embedded `history`, `redFlags[]`, and `physicianEdits[]` inside `CaseRecord`; referenced `MedicalDocument` (1:N); `PhysicianAssignment` junction collection (M:N); startup `collMod`/`createCollection` `$jsonSchema` validators. | `server/src/models/validators.js`, `server/src/models/*.js`, `server/src/tests/models.test.js` |
| **CO4** | Construct single-field, compound, unique sparse, text, TTL, and covered indexes, and build multi-stage aggregation pipelines (`$group`, `$unwind`, `$lookup`, `$unionWith`) with `explain("executionStats")` benchmarking. | 5 aggregation endpoints under `/api/analytics/*`; compound indexes `idx_case_patient_created` and `idx_case_triage_queue`; covered query (`totalDocsExamined: 0`); 100,000-document benchmark in `scripts/benchmark.js`. | `server/src/controllers/analytics.controller.js`, `server/src/scripts/benchmark.js`, `docs/performance-report.md` |
| **CO5** | Implement secure full-stack NoSQL applications with JWT authentication, role-based access control (RBAC), input validation (Zod), and privacy/consent governance. | JWT bearer authentication, `authorize('patient', 'physician', 'triage')` RBAC rules, patient data isolation, revocable consent toggles, and React + Vite + Tailwind + Recharts frontend. | `server/src/middleware/auth.js`, `client/src/**`, `server/src/tests/api.test.js` |
| **CO6** | Integrate intelligent rule-based / AI-augmented decision support over semi-structured NoSQL clinical documents. | Clinical Red-Flag Engine (`RF_ACS_01` through `RF_SEVERE_PAIN_06`) and automated Abnormal-Lab Flagger evaluating `CaseRecord` and `MedicalDocument` payloads on submission to drive the real-time triage priority queue. | `server/src/services/redFlag.js`, `server/src/services/redFlagRules.json`, `server/src/tests/redFlag.test.js` |

## 2. Syllabus Unit Mapping (Units I – VI)

| Syllabus Unit | Core Topics Covered | MediKiosk Modules & Files |
| :--- | :--- | :--- |
| **Unit I: Introduction to NoSQL & Document Databases** | BSON data types (`objectId`, `date`, `array`, `object`, `number`), document store architecture, horizontal scalability, Atlas readiness (`MONGODB_URI`). | `server/src/config/env.js`, `server/src/config/db.js`, `.env.example` |
| **Unit II: MongoDB CRUD & Query Operators** | `insertOne`, `insertMany`, `find`, `findOneAndUpdate`, `deleteMany`, query operators (`$in`, `$gte`, `$text`), cursor sorting, skip/limit pagination, cascading deletes. | `server/src/controllers/patient.controller.js`, `server/src/controllers/case.controller.js`, `server/src/controllers/document.controller.js` |
| **Unit III: Data Modeling & Schema Validation** | Embedding vs. referencing, BSON 16 MB limit analysis, 1:1 (`User`–`Patient`), 1:N (`Patient`–`CaseRecord`/`MedicalDocument`), M:N (`PhysicianAssignment`), Mongoose schemas + native MongoDB `$jsonSchema` via `createCollection`/`collMod`. | `server/src/models/validators.js`, `server/src/models/*.js`, `docs/schema-design.md` |
| **Unit IV: Indexing, Aggregation Pipeline & Performance Tuning** | Compound indexes (ESR rule), unique sparse index (`abhaId`), multi-field text index, partial TTL index (`status: "draft"`), covered queries (`PROJECTION_COVERED`), `$group`, `$dateToString`, `$unwind`, `$lookup`, `$unionWith`, `explain("executionStats")`. | `server/src/models/CaseRecord.js`, `server/src/controllers/analytics.controller.js`, `server/src/scripts/benchmark.js`, `docs/performance-report.md` |
| **Unit V: Application Security, Auth & Full-Stack Integration** | JWT authentication, `bcryptjs` password hashing, RBAC middleware, Zod payload validation, central error handling, patient consent management, React + Recharts visualization. | `server/src/middleware/auth.js`, `server/src/middleware/errorHandler.js`, `client/src/**` |
| **Unit VI: Intelligent NoSQL Applications & Clinical Decision Support** | Rule-based clinical inference over JSON/BSON documents, automated triage priority scoring, abnormal laboratory reference-range evaluation, real-time priority queue. | `server/src/services/redFlag.js`, `server/src/services/redFlagRules.json`, `server/src/controllers/triage.controller.js` |
